# Tools Discoverability from Dashboard

## Status

📝 Defined — recorded by the founders on 2026-09-01 as a **saved product idea** alongside the Sprint 4 reorder. **Deliberately not decided.**

**⏸️ Deferred at the Sprint 4 closeout, 2026-09-01 — deferred, not cancelled.** Sprint 4 closed as **Settings + Tools Foundation** after its two foundation slices, and this remains a valid product direction. The reason is sequencing, not doubt: this is presentation-heavy work, and the founders are defining a new VITA visual and interaction language next. Building it now would mean designing it twice. It resumes once that language exists — and lands into the `/tools` architecture slice 4.2 already established, where a new tool is a row and a route rather than a question about where it belongs.

**Its own precondition is now met**, which is the one thing that changed: this note said *build the Tools destination first, then evaluate whether discoverability is actually a problem*. Slice 4.2 built it. The evaluation still has not happened, and **no [[Dashboard]] card is authorised.**

Original note follows. Exact placement is open, and **no [[Dashboard]] card is authorised.**

## Category

[[UX Improvements]]

## Priority

Low — it is a refinement of something that does not exist yet. The Tools destination has to be built and proven before its discoverability is a real problem.

## Estimated Difficulty

Low to build, genuinely hard to justify. Home is the most contested surface in VITA and the founders have twice asked for it to be left alone.

## Recommended Tier

Free.

## Problem

If Tools live only behind Settings → Tools & Reference, a user who would benefit from the Peptide Calculator or the BMI Calculator may never learn they exist. Settings is where people go to change something, not to discover something.

## Solution

Eventually surface Tools from Dashboard/Home — **if product design supports it.**

**What is explicitly not decided:** whether it is a card, a row, a header affordance, or something else · whether it is permanent or contextual · whether it appears for every user or only for users with a relevant routine.

## User Experience

Undecided by design. Any proposal is evaluated against the standing Home rules: Home is the visual source of truth, it is not a launcher, and it does not accumulate entry points because a feature would like one.

## Why Users Would Love It

Useful tools found rather than hunted for.

## Business Value

Increases usage of features already built. That is genuine value and also the exact argument every feature makes for a place on Home, which is why this stays an idea rather than a plan.

## Dependencies

- **The Sprint 4 Tools & Reference destination must exist first.**
- Founder design decision on Home placement — [[Dashboard]], [[Navigation & Floating Dock]].
- The primary-navigation question for [[Water]] and [[Peptides]] ([[Open Questions]] #4), which this overlaps.

## Future Enhancements

Contextual surfacing — showing the calculator to someone who has an active peptide routine and nothing to anyone who does not.
