## Unreleased

- 2026-08-25 — **Sprint 3 slice 3.6C — the calculator says one thing.** Founder review of 3.6B asked for a final simplification: the screen answers *given this concentration and this amount, how many syringe units is that?*, and should say nothing more. **Syringe units are now the only output.** The domain still normalises to micrograms internally, but micrograms never surface as a result — no second mcg figure, no `1 unit = X mcg`, no units → mass converter, no reference table. Every extra output is another number competing to be the one the user acts on, and only one of them gets drawn into a syringe. **The result hierarchy was rebuilt** so units are the only display-size text: equivalent volume moved out from under the headline into the supporting block alongside concentration, the compact working, and the U-100 line. **Renamed** *Amount being used* → **Amount**, and the section to **Unit calculator**. **Switching mg ⇄ mcg now converts instead of reinterpreting** — `2 mg` becomes `2000 mcg` and the answer does not move; `500 mcg` becomes `0.5 mg`. This is the most dangerous thing the screen could get wrong, since reinterpreting would shift the amount by a factor of a thousand while the digits sat still, so it is pinned by a round-trip test in both directions. Two guards: only a **complete** number is rewritten (`Number('1.')` is `1`, so parsing alone would turn someone half-way through typing "1.5" into "1000"), and the conversion is a single explicit action on press rather than an effect reacting to state, so there is no loop, no bouncing value and no cursor fight. **Preferred unit now seeds the calculator once and then lets go** — it previously read the preference on every render, so changing *Preferred unit* lower down the form silently reinterpreted an amount already typed above it; they are separate concepts, the same correction made about Water's display unit in slice 3.3. Unchanged and re-verified: inline placement under the Vial section, calculation from live draft state with no Save required, the section staying visible with a helper line when the vial is incomplete, the U-100 assumption with no capacity selector, the Done accessory, the standalone Tools calculator, the removed setup-specific route, and `Save setup` persisting no calculator state. **10 new tests, 625 total.** Verified on device in Light and Dark: 20 mg / 2 mL / 2 mg → 20 units, and 5 mg / 2 mL / 500 mcg → 20 units with concentration correctly shown as 2.5 mg/mL in the vial's own unit. ⚠️ **Typing is still proven by tests rather than by hand** — no tap or type access to a simulator — so founder confirmation on a real iPhone remains the acceptance gate. Noted but not changed: the *vial* unit toggle still reinterprets rather than converts, because it feeds a value that gets saved. Still open: the **Track this peptide** CTA discoverability item. **No logging (3.7), no injection sites (3.8), no catalog content changes.** (Slice 3.6C)

- 2026-08-25 — **Sprint 3 slice 3.6B — the calculator moves to where people need it, and the keypad can be closed.** Founder device QA on 3.6 showed the *design* was wrong, not just the implementation: the only way to reach a calculator was through a peptide setup you had already created, and iOS's decimal pad has no return key, so the keyboard could not be dismissed. A calculator that requires you to first create a tracked peptide is one you cannot use with a vial in your hand — working out how many units to draw is a question, not a record. **Two surfaces now, one calculator**: **inline** in the peptide setup form, reading the live draft text in the fields above it, and **standalone** at Settings → Tools → Peptide Calculator, which needs no peptide, definition or setup at all. `DoseCalculatorPanel` is the single component behind both, so they cannot drift in arithmetic, wording, validation or layout. **The inline calculator works before anything is saved** — type 20 mg, 2 mL, 2 mg and the answer appears with no Save and no navigation; changing the vial, water or unit recalculates immediately. Placement follows the approved hierarchy exactly: NAME → VIAL → **CALCULATOR** → PREFERRED UNIT → SCHEDULE → START DATE → NOTES → Save, directly under the vial it depends on rather than buried at the bottom. **The amount is owned by the panel and never leaves it**, which makes "the calculator persists nothing" structural rather than a rule to remember — `Save setup` cannot capture it because it cannot see it, asserted by test. **The section stays visible when the vial is incomplete**, with one line saying what is missing. **The keyboard defect is fixed**: new `NumericField` and `NumericKeyboardAccessory` put a **Done** bar above the pad through `InputAccessoryView` (iOS-only, guarded), one accessory per screen shared by every numeric field, and `Screen` gained an **opt-in** `keyboardAware` prop — tap-outside dismisses instead of being swallowed, dragging dismisses, and extra bottom padding lets a form's foot clear the keyboard. Opt-in so no existing screen changes behaviour. **The old `/peptides/setup/[id]/calculator` route and its button are removed** — inline covers the in-context case, Tools covers the standalone one, and a third destination would be duplicate navigation. **Tools** is a new Settings destination for utilities that stand on their own, deliberately not a fifth dock tab, built to host slice 3.8's injection-site tools with **no placeholder rows** in the meantime. **Accessibility**: `PressableScale` now announces `accessibilityRole="button"` whenever it has an onPress — the app-wide gap recorded in 3.6A — and `SegmentedTabs` gained a `groupLabel`, because three identical mg/mcg toggles on one screen gave a screen-reader user three indistinguishable "mg" buttons and now read "Vial unit, mg" and "Amount unit, mg". **37 new interaction tests, 615 total** — the coverage 3.6 lacked: they start from an empty form and type into fields located by accessibility label in the rendered tree, instead of handing a component values the UI would have had to produce. Verified on device in Light and Dark. ⚠️ **Typing itself is proven by the interaction tests, not by a device** — tapping and typing remain unavailable from the engineering environment, so founder confirmation on a real iPhone is the acceptance gate. Still open: the peptide detail **Track this peptide** CTA discoverability item. **No logging (3.7), no injection sites (3.8), no catalog content changes.** (Slice 3.6B)

- 2026-08-24 — **Sprint 3 slice 3.6 — the dose / unit calculator.** A user enters the amount they are using and VITA returns the number of units to draw: a 10 mg vial in 1 mL is 10 mg/mL, so 2 mg is 0.2 mL, which on a U-100 scale is **20 units**. **VITA converts; the user decides** — every mass on the screen originates from something the user typed, and `model/dose.ts` is pure and lives outside every screen precisely because arithmetic that cannot reach state cannot quietly acquire an opinion. No function in it has a "recommended" or "typical" input to supply one. **Canonical micrograms throughout**, with both directions sharing one concentration resolver, which is what makes the inverse a genuine inverse rather than a second hand-written formula that agrees by coincidence — asserted by a round-trip over sixteen vial/amount combinations rather than restated literals. **The result is a discriminated union**: either every field is meaningful or none is, so a failure carries no numbers to misread, and nine typed reasons separate *missing* from *invalid*. **Full precision internally, rounded once at the display edge** — `20 units`, `2.5 units`, `13.3 units` for a third of a vial, never `13.333333333333`; volume keeps three decimals because `0.025 mL` is real in this domain. **V1 assumes U-100 · 100 units/mL** and says so beside every result as context, not a warning; **no syringe-capacity selector**, since 0.3, 0.5 and 1 mL syringes are all U-100 and the control conflating those was removed in 3.5B. `unitsPerMl` stays on the model so another scale needs no migration. **New route `/peptides/setup/[id]/calculator`**, reached from the setup screen — its own route because editing a setup and converting an amount have different lifetimes, and folding them together would make Save feel like it saved the amount. **Vial and water are prefilled from the setup and derived every render**, never cached: reseeding 1 mL → 2 mL moves the concentration 10 → 5 mg/mL and the answer 20 → 40 units, verified on device. **Incomplete setups are refused, never guessed** — a fabricated 10 mg / 1 mL default would give a confident wrong number to someone whose vial is neither. **Nothing is persisted**; a test asserts zero repository writes across typing, switching units and retyping. **Reverse conversion is implemented and tested, its UI deferred** — the founder's primary flow is Amount → Units, and a mode switch nobody has asked for would trade one obvious flow for an option. **Data-consistency notes, not medical judgements**: 12 mg on a 10 mg vial still calculates (120 units, 1.2 mL) and gets one neutral line, with a test forbidding *split*, *two injections*, *divide the dose*, *too much* and *maximum*. **A real defect surfaced in testing** — the shared `parseAmount` collapses an empty field, `"0"` and `"abc"` to the same `null`, so the screen now classifies the text before the domain sees it: blank stays silent, zero says something. **77 new tests, 605 total.** Verified on device in Light and Dark across six states. Recorded but not fixed: the shared `Button`/`PressableScale` set no `accessibilityRole="button"` — app-wide, pre-existing, outside this slice's boundary. **No logging (3.7), no injection sites (3.8), no catalog content changes.** (Slice 3.6)

- 2026-08-24 — **Sprint 3 slice 3.5C — the peptide pages now say what a compound does, in English.** After 3.5B a detail page could be accurate and still useless: *"inhibits nicotinamide N-methyltransferase"* answers nothing, and *"Not FDA-approved"* is true of nearly the whole catalog. Two new sections fix that. **Research claims** answers *what* — short labelled blocks, **each carrying its own evidence label**, because one compound can have strong human evidence for one effect and vendor folklore for another and a single page-level badge would launder the second into the first. A claim marked limited must qualify itself **in words**, not only in a badge; preclinical claims must attribute themselves to animal or laboratory work; `approved-use` is reserved by test for compounds that hold an approval. **How it works** answers *how*, explained rather than recited. **A new development-status model replaces the regulatory binary**: a typed stage (approved · submitted · phase 3/2/1 · early human · preclinical · not in clinical development · discontinued), a summary, an optional next milestone, `lastUpdated`, and its own sources — with the heading switching to **Approval status** for approved medications. Sermorelin now reads *Discontinued — withdrawn from the US market in 2008 by the manufacturer; a commercial withdrawal, **not an FDA safety action and not a rejected application***. **A stated plan is rendered as a plan**: "Lilly has said it plans to submit retatrutide to the U.S. FDA in Q1 2027" is a fact about an announcement, where "approval expected" would be a prediction VITA has no standing to make — the build fails on *will be approved*, *approval expected*, *awaiting approval*, *guaranteed*, *FDA denied*, *FDA rejected*, *refused approval*. **Time-sensitive pipeline facts were researched against current sources rather than authored from memory**, and every stage that can change must carry both a date and references — **recorded as recurring maintenance debt**, since a phase stated without a date asserts permanent truth about something that moves. **Cross-compound contamination is now caught by test rather than by eye** — the founder flagged Semax carrying Semaglutide's content, an error invisible to anyone who does not already know both compounds. Fixed in content (*"Feeling full after a meal"*, *"Energy burn and the liver"*, *"Prompting your own growth hormone"*, *"Supporting neuron growth"*) **and** structurally, with a test forbidding any mechanism title contained in its own target. **Sections render only when populated** — a sparse compound gets a short honest page, not an empty heading. **50 new tests, 510 total**, including the first tests to render the detail route itself, since every one of these sections sits below the fold and the simulator cannot scroll. ⚠️ **All research content remains engineering-authored with no medical or legal review** — Open Question #17 stays open. **No calculator (3.6), no logging (3.7), no injection sites (3.8).** (Slice 3.5C)
