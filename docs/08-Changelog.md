## Unreleased

- 2026-08-21 — **Fuel polish + barcode QA.** Founder approved the `dee1ddf` Fuel redesign; its layout is now locked. Four follow-ups: (1) **Copy** — `cal eaten` → `Calories consumed` beside `Calories remaining`, and macros read as progress toward the user's configured targets (`Protein Goal · 30 / 160 g`), with no warning state at 100% and no invented dietary rules. (2) **Food images were being destroyed by persistence** — `parseCustomFoodShape()` rebuilt stored foods field by field and never copied `imageUrl`, and because `toggleFavorite` rewrites the already-parsed array, the next toggle erased the image from storage permanently; the stripped favorite then shadowed the intact cached copy in `findFood()`. Fixed at the source: the read path preserves `imageUrl`/`restaurant`/`dataQuality`, and `FoodEntry` gained an `imageUrl` snapshot so a logged food renders from its own history with no lookup. `restaurant` and `dataQuality` were silently lost the same way and are also restored. (3) **Contextual food visuals** — a shared three-tier resolver (real provider image → VITA category visual → generic) with 24 categories and conservative order-sensitive matching, used by Fuel's meals, Search, Recents, Favorites, Food Detail, and Edit Entry through one `FoodAvatar`. **Architecture only — custom VITA artwork is NOT done**; categories currently share stock glyphs and are the thing artwork will replace. (4) **Kroger barcode — still open.** The previous round's "Open Food Facts data is not mislabelled" conclusion was wrong: OFF record `0011110816405` sits under Kroger's GS1 company prefix `0011110` but carries Hillshire Farm "BEEF SMOKED SAUSAGE" name, brand, imagery, and nutrition. Upstream data corruption, which every VITA-side identity check correctly confirms because the code returned *is* the code requested. Not fixed and not worked around — nothing hardcoded, special-cased, or text-matched. The trace now covers camera → normalization → provider identity → navigation → Food Detail → **log snapshot** → Edit Entry, and renders on both Food Detail and Edit Entry; one physical scan will confirm the code.

- 2026-08-21 — **Sprint 2 slice 2.9, Fuel Visual Refinement:** the Fuel landing screen rebuilt as a daily nutrition command centre rather than a menu of cards. Calorie ring + Calories-remaining headline + macro bars in one summary card; a prominent **Log Food** action beside **Scan Barcode**; **Today's Meals** as four rows in a single panel — expanded meals show their actual foods with serving, calories, and a favorite heart, empty meals are compact one-line rows, and every meal has its own `+ Add food` that deep-links the existing logging flow with that meal preselected (a validated route parameter, not new state); Hydration and Peptides reduced to half-width secondary modules. New warm meal color progression — Breakfast yellow, Lunch orange, Dinner sunset red, Snacks neutral sage with a utensils glyph (**not** the reference's purple, which is a locked Atlas/peptide domain color). **`kcal` removed from user-facing copy app-wide** in favor of `Calories`/`cal`; internal field and provider names deliberately unchanged. Presentation and information architecture only — no provider, search, ranking, barcode, logging, editing, favorite, persistence, or theme behavior changed, and no mock nutrition data added. Verified in Expo Go on the iOS Simulator in both an empty and a populated day, Light and Dark. **Tap-dependent paths remain unverified** — the simulator can be screenshotted but not driven — and need the founder's physical iPhone. (Slice 2.9)

- 2026-08-19 — **QA round 2.** Favorite hearts added to logged food rows and the Edit Entry header, both built from the entry's stored snapshot so no provider request is needed. `Add to Log` now unwinds the whole logging stack with `dismissAll()` and returns to Fuel instead of leaving the user several Back presses deep; Save/Delete return to the Food Log. Barcode misidentification is **still unresolved** — a dev-only end-to-end scan trace was added to identify it from a physical device, since no test had used the actual bottle's barcode.

- 2026-08-19 — **QA repair: barcode misidentification + favorite discoverability.** A scanned barcode could display an unrelated earlier product — `/fuel/food/[id]` updates params without remounting, so a `useState`-seeded food never refreshed and every subsequent food showed the first one. Same defect fixed in the entry editor. Open Food Facts barcode lookups now re-verify the returned GTIN and reject mismatches; the barcode chain now runs Open Food Facts first as designed, instead of spending a futile USDA request on every scan. Favorite hearts (present since 2.7 but drawn too faintly to find) now render as visible circular controls.

- 2026-08-19 — **USDA live verification: reliability + ranking fixes.** Removed the `dataType` query parameter, which api.data.gov intermittently rejected with nginx `400` on **5 of 10** identical requests (unfiltered: 10/10) — it was silently costing USDA results on about half of all searches. Filtering moved client-side. Also removed a `hasCompleteMacros` ranking bonus that rewarded food type rather than data quality, pushing "Bread, egg" above real eggs.

- 2026-08-19 — **USDA ranking fix.** Real FoodData Central responses showed bare generic queries returning branded junk first — a peanut butter spread named "BANANA" above "Bananas, raw", three products named "EGG" above real eggs. Added `VitaFood.dataQuality`, a provider-independent per-record trust signal (USDA maps its FDC data types; Open Food Facts uses a flat value), reduced the exact-name bonus for branded products whose brand the query never mentioned, and added a capped extra-word penalty. All slice 2.6 field and per-100 g normalization assumptions were confirmed correct.

- 2026-08-19 — **Sprint 2 slice 2.8, Barcode Scanner:** real camera barcode scanning via `expo-camera` on SDK 54 (Expo Go, no dev build, no Xcode). VITA scanner chrome, full permission handling, a synchronous `ref` scan lock against repeat callbacks, torch, and a sequential Open Food Facts → optional USDA lookup chain that distinguishes "product not found" from "lookup failed". Fixed: OFF returns HTTP 404 for unknown barcodes, which was surfacing as a retryable error instead of not-found. Live detection still needs a physical iPhone. (Slice 2.8)

- 2026-08-18 — **Sprint 2 slice 2.7, Recents + Favorites:** Recent Foods is derived from real logging history (30 days scanned, 25 rows, one row per food identity, most recent first) with no parallel store — the reserved `recents` storage key was deleted rather than filled. New `foodFromEntry()` rebuilds a loggable food from an entry snapshot alone, so recents work offline and outlive their provider cache. Favorites persist keyed by `vitaId`, with provider-aware storage of the food definition (`fatsecret` excluded pending terms review) and provider-independent presentation. The heart returns to search/recent rows and Food Detail. (Slice 2.7)

- 2026-08-18 — **Sprint 2 slice 2.6, Provider Layer + Real Search:** food search is now backed by real providers. USDA FoodData Central and Open Food Facts adapters behind a `FoodProvider` interface, feeding normalization → parallel fan-out → GTIN-normalized deduplication → deterministic ranking → TTL cache. The interim fixture catalog and its `'vita-fixture'` source are retired, with Search/Food Detail/Edit unchanged — the proof the abstraction works. Open Food Facts verified end-to-end on device; **USDA blocked pending a free API key from the founder.** Both providers are $0 with no billing risk. (Slice 2.6)

- 2026-08-18 — **Sprint 2 slice 2.5, Home Synchronization — one source of truth achieved.** Home's calories, macros, and meals now come from the same `src/lib/nutrition` engine as Fuel; `DASHBOARD_FIXTURE`'s `calories` and `mealSlots` are gone, and Dashboard's `MealSlot` is a re-export of the canonical type. Only the nutrition goal pillar is derived — Water/Movement/Recovery stay honestly fixture-driven. **No file under `src/features/dashboard/components/` changed** (verified byte-identical). (Slice 2.5)
